What changed, and why

Numbers match the “Annotations” toggle. Each note names where the change lands.

1 · The compact header loses 54px of nothing

The dead band is not a layout choice — it is trafficLightPosition: {x:16, y:25} parking the close dot 25px down, and pt-[54px] clearing it. Move the dot to y:13, x:14 and the brand, expand, pin and overflow all fit one 42px bar with nothing above it.

Net: about 60px back, which is a whole extra action row in a 520px window. Nothing native is given up — the dot is still the real close button, and window drag still works.

tauri.conf.json · CloudMiniInbox.tsx header

1b · Expand means full window, and says nothing

The icon loses its label. It sits beside pin and overflow, and a word on one of three identical-weight controls is chrome the 42px bar cannot spare — the surface fill already makes it the primary of the three.

What it does changes: expanded stops being a 1180×760 card and becomes the monitor's work area. WINDOW_SIZES.expanded turns from a constant into a value read from workArea(), which applyWindowMode already fetches — today only to clamp the position afterwards. Minimums stay (960×640) and expanded stays unpinned.

One consequence: the conf-vs-constant test only covers compact after this, because expanded no longer has a fixed size to check against.

windowMode.ts — WINDOW_SIZES, applyWindowMode, windowMode.test.mjs

2 · Counts move up into the reclaimed space

The summary line and the three lane counters now sit where the empty band was, so the first action row starts around y=100 instead of y=175.

CloudMiniInbox.tsx — InboxSummary, InboxBody

3 · Search is chrome, not a page feature

Pulse, Inbox and anything added later all need it, so it lives in the window bar at every width and opens the same palette from ⌘K. One surface indexes milestones, events and people — an event match is often the fastest way to the milestone.

CloudShell.tsx · new cloudSearch feature

4 · The sidebar comes back — and this reverses my last note

I proposed cutting it to a 56px rail when the window held two views. At 247 milestones that was wrong: the column now carries saved views, status, team and source, which is what keeps the list from being everything at once. Nav stays on the 52px rail; the facets are a second column that belongs to Pulse.

CloudShell.tsx · PulseFacets (new)

5 · Answer before list

“Regressed 6 · blocked ≥5d 3 · went quiet 5 · closed out 18” is the thing a lead opens Pulse to learn, and today it can only be reconstructed by scrolling. Each tile is also the filter for its own set, so the summary is the way in.

“Went quiet” is a state Cloud can derive but never names today — a milestone with no events for 14 days looks identical to a healthy one at a glance.

new overview endpoint or client-side rollup

6 · The list says what it is showing

Active view as a removable chip, “14 of 247”, and a sort control. With facets in play, a list that does not state its own filter is a list you cannot trust.

PulseMilestones.tsx

7 · One row per milestone, not one card

A 24px-padded card with a full 30-day rail is ~210px tall — three fit on screen, so 247 milestones is 80 screens of scrolling. The row is 44px: subject, team, status, open count, a fixed-width sparkline of the same compressed stages, last observed. Eleven fit, and the comparison the eye wants (which of these is worse) finally happens within one screen.

The rail logic does not change. railStages() already compresses runs and gaps; the sparkline is that output at a smaller size with the labels dropped.

MilestonePanel.tsx → MilestoneRow.tsx, MilestoneRail.tsx

8 · The card becomes the detail panel

Nothing is lost — the full rail, the counts, the stage record and the event list all move into a panel that opens on row click. That panel is where a rail node is big enough to aim at, and it is the only place that needs to be.

MilestonePanel.tsx, StageRecord.tsx, CloudThreadPanel.tsx

9 · Search returns events, not just titles

Scoped tabs across milestones / events / people, keyboard-first, matches highlighted. Searching “read state” should find the day the gateway rejected 44200, not only the milestone whose title contains those words.

gateway search endpoint · cloudSearch

10 · The expanded inbox stops being the compact one, enlarged

It was a 380px list rendered at 900px — same rows, more whitespace, and 340px of column doing nothing. A wide window should buy something the narrow one cannot: facets, a list, and a reading pane where the action is actually worked.

The compact window keeps the single dense list. That is the right answer at 380px and the wrong one at 1180px, which is why CloudInboxPane re-rendering InboxBody was never going to hold.

CloudInboxPane.tsx — no longer shares InboxBody

11 · Actions and milestones stop being two products

An action carries an entity, and a milestone's open counts are made of actions — but nothing in either view says so. The milestone is a facet here, a line on every row, and a crumb in the reader that jumps to Pulse. Same fact, three places you would want it.

Action.entity ↔ Milestone.open · cloudGateway/types.ts

12 · One row, three lanes, no repeated chips

Rows are 62px and carry priority, action kind, age, subject, source and milestone. Lane headers stay sticky, so “blocked” is still visible when you are ten rows into “today”. Left edge is tinted by lane — selection overrides it, so the two never argue.

CloudInboxPane.tsx — ActionRow (wide variant)

13 · The reader answers “why is this mine?”

Today a row states the obligation and the instruction, and the source thread lives one window away in Pulse. Here they are the same pane: the reason line, the conversation with the triggering message marked, and the other open items on the same milestone.

Actions are navigation only — open the source, open the milestone. Cloud defines no mutation on an action, so there is no Done, no Snooze, and the footer says so rather than leaving you to discover it by pressing something that does nothing.

CloudThreadPanel.tsx moves into the reader

Open question — grouping

The table sorts; it does not group. If teams want “by team, collapsed” as the default at 247 rows, that is a different default than “needs attention first”, and it changes what the facet column is for. Worth deciding before this gets built.
