# Compact-window foundation

## Summary

Configure Gear6's desktop window to launch compact and always-on-top, while preserving native resize, maximize, and drag-to-top behavior. Defer all Open Loop data and UI rendering.

## Implementation changes

- Update the Tauri main-window configuration to launch at `380x520` logical pixels, with `320x360` minimums, `maximized: false`, and `alwaysOnTop: true`.
- Keep the window resizable and maximizable so OS-native maximize and drag-to-top expand behavior remains unchanged.
- Retain the existing window-state plugin: it restores the user's prior size, position, and maximized state after the first launch.
- Do not alter `Gear6Root`, `AppShell`, backend/API models, or render any compact/expanded UI in this phase.
- Do not add a frontend pin toggle yet. The eventual compact UI will own the persisted pin preference and call Tauri's native `setAlwaysOnTop`; until then, each new launch begins pinned.

## Test plan

- Validate the Tauri configuration through a desktop build/startup check.
- On a fresh window-state profile, verify the app opens compact and stays above other applications.
- Verify native maximize and dragging to the top edge expand the window normally.
- Verify restoring/unmaximizing retains normal platform behavior and that reopening preserves size/maximized state.

## Assumptions

- This is desktop-only behavior.
- Compact-and-pinned is the initial default; visual controls, Open Loop content, and the new AppShell-based workspace are deferred.
